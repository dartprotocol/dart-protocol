Hybrid Architecture

Bridging the gap between raw UDP hardware performance and universal Web accessibility.

Dual-Transport Topology

Dart handles transport fragmentation natively. The central server maintains a unified peer list, seamlessly routing raw UDP datagrams to native CLI clients, and framed TCP/WebSocket payloads to Browsers and Electron apps, without breaking protocol state. A TCP fallback transport (port 9001) covers high-loss or NAT-traversal cases.

Blind, Server-Blind Relay

The server is a pure router: it relays opaque ciphertexts and never holds a conversation key. Membership is public, content is not — the server cannot read a single message, and it fans out the exact same encrypted bytes to every member.

In-Memory Sliding Window

For lightning-fast NACK recovery, servers and clients maintain a bounded Sliding Window Cache (max 200 packets per peer). When a gap is detected, packets are pulled directly from RAM — zero database lookups, instantaneous repair.

Member-to-Member Key Exchange

The first member of a room becomes its creator and generates the group key. New members publish their public key, receive a server-authenticated roster, and are handed the key via per-member KEY_SHARE — ECDH-encrypted all the way.

Where Dart Wins

Steady state, Dart sends ~33–48% fewer packets than a positive-ACK chat, converging toward the ~50% ceiling as groups grow — it sends zero ACKs per message where the baseline sends one per receiver. The gain grows with loss (44% at 10% → 50% at 30%): a NACK-only model costs less than ACK + retransmit once the link degrades. Delivery stays ~100%.

Honest Limits

A synchronized 50-sender burst saturates the single-threaded client receive path (UDP socket overflow); the realistic staggered pattern recovers to 99.5% — a client-throughput limit, not a protocol failure. Joining a room is O(N²) membership traffic, and WebSocket clients still inherit TCP's head-of-line blocking (the V2 WebTransport roadmap fixes that).

Cryptographic Core

The relay server is blind. Group keys are generated by a room member and shared member-to-member — never seen by the server.

End-to-End Group Keys

The room creator generates the per-conversation key; every member receives it as an ECDH-encrypted KEY_SHARE, relayed opaquely by the server. The server only ever sees public membership, never key material.

Epoch Rotation (Forward Secrecy)

Group keys carry an epoch. The creator rotates the key on a timer and when a member leaves, so a compromised key only exposes its own epoch. Old epochs are pruned after a short window.

AES-256-GCM + Random Nonces

Every packet is encrypted and authenticated under the current epoch's key with a fresh random 12-byte nonce — no nonce reuse, no implicit-IV collisions. Data darts also carry a dictionary fingerprint so loss recovery is deterministic.

Server Key Pinning

Servers persist a long-term ECDH identity key and print its SHA-256 fingerprint. Clients pin it and abort if the roster's server key doesn't match — blocking man-in-the-middle substitution.

Bounded Compression Dictionary

Delta compression uses a deterministic 200-message per-sender window with a 4-byte SHA-256 fingerprint in every header, so desyncs are detected before inflation and recovered in one step — with bounded client memory.

Authenticated Control Frames

ACK, NACK, SYNC and Dict Reset are GCM-authenticated under the group key, so outsiders can't forge delivery confirmations or force dictionary resets.

Where It Stands

Honest status: what works today, what's deliberately next.

Working Today

Real E2EE group keys with a server-blind relay, epoch-rotation forward secrecy, NACK-only reliability, bounded dictionary compression with fingerprint recovery, server key pinning, TCP fallback, and verified interoperability across TypeScript, Go and Rust.

Next Up (Roadmap)

Per-message ratchet (MLS/Double Ratchet), real PKI instead of fingerprint pinning, per-member control-frame authentication, browser WebTransport for true UDP in the browser (V2), and — as a separate architecture — P2P mesh routing to hide conversation metadata.
